## 2. 建议补充的 2 项（原画布没有，但企业化会遇到）

1. **计费主体（Billing Entity）**：组织/部门成本中心；与多租户一起做，避免二次改表。
2. **SSO / SCIM**：企业客户基本会要求 OIDC/SAML 与账号同步。上游已有 OAuth/OIDC 基础，可扩展；P2 才做。

## 3. 与 P0/P1 的边界

- P2 **不**改现有用户/分组语义：组织是叠加层，`users` 表不塞组织字段（画布已明确「独立表」）。
- 窗口限额、脱敏、审计都已有 `scope_type` / 事件模型，P2 复用即可，不推翻 P0/P1。
- 自家 agent 统一走 wings-api 属于部署配置，不写代码。
